# Формы заявок и Telegram

Общая форма открывается сразу по CTA на всех страницах. На главной также есть две независимые формы: после услуг и в нижнем блоке контактов. Проверки имени, белорусского номера и согласия выполняются в браузере и повторно в `lead.php`.

## Приватная конфигурация

Токен хранится только на хостинге, в переменных `VERTO_TELEGRAM_BOT_TOKEN` и `VERTO_TELEGRAM_CHAT_ID`, либо в `verto-private/telegram.php` рядом с корневой папкой сайта, **вне публичного доступа**:

```php
<?php
return [
    'token' => '<токен от BotFather>',
    'chat_id' => '436390507',
];
```

Для сайта `/www/verto.by` используется `/www/verto-private/telegram.php`. Права приватных папок — 0700, файлов — 0600. Для другого пути задайте `VERTO_LEAD_CONFIG`. Токены и заявки не должны попадать в GitHub или публичную папку. Нужны PHP 7.4+, исходящий HTTPS к `api.telegram.org` через cURL или `allow_url_fopen` и право PHP на запись в приватную папку. Общая временная папка PHP не используется.

## Резерв заявок

После проверки и ограничения частоты запросов обработчик **сначала** записывает заявку в `verto-private/leads/<id>.json`, затем отправляет уведомление в Telegram. Хранятся имя, телефон, услуга, страница, место формы, согласие, время UTC и статус доставки. Токен и полный URL Telegram не сохраняются.

Статусы в `delivery.status`:

- `sent`: Telegram подтвердил доставку; сохранён `message_id`.
- `failed`: заявка принята и сохранена, Telegram недоступен или не настроен.
- `pending`: исходная запись сохранена; отправка ещё идёт или обработка прервалась. Такую запись нужно проверить вручную.

Скачать заявки можно по FTPS из приватной папки `leads`; веб-доступа к ним нет. Заявки со статусами `failed`/`pending` требуют ручной обработки. Автоматической повторной отправки нет. Для другого приватного пути задайте `VERTO_LEAD_STORAGE_DIR`; путь внутри публичной папки обработчик отклоняет. Удаление записей выполняется уполномоченным сотрудником согласно срокам обработки персональных данных компании.

Успех формы означает, что заявка надёжно записана: HTTP 200 при доставке в Telegram или HTTP 202 при сохранении без подтверждения доставки. Если запись невозможна, обработчик возвращает ошибку и браузер сохраняет введённые данные. Повтор запроса с тем же `request_id` не создаёт второй записи и не отправляет повторное уведомление. Изменённые данные требуют нового ID; формы создают его автоматически. Файлы `.lock` предотвращают параллельную обработку одного ID — не удаляйте их во время запросов.

Ограничение спама — 5 запросов за 10 минут на хеш IP в приватной папке `rate-limit`; путь меняется через `VERTO_LEAD_RATE_DIR`. Honeypot не создаёт заявки и не вызывает цели формы.

## Проверка и аналитика

Получатель должен открыть бота и нажать «Начать». После публикации отправьте явно обозначенную тестовую заявку, проверьте приватный JSON и сообщение в Telegram. При недоступности Telegram контакт должен остаться в JSON. Старые заявки до включения хранения восстановить из этих файлов невозможно.

Метрика `114134032` и Meta Pixel `1881270919425529`/`2239115797039785` работают на `verto.by` и `www.verto.by`. Цели `lead_form` и `Lead` формы вызываются только после подтверждения сервером сохранённой заявки. Существующие события `Lead` при переходе в Telegram/Viber сохранены; такие клики сами по себе не означают отправку формы.
